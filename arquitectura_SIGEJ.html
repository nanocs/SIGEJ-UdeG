1. Resumen ejecutivo y estado actual

El SIGEJ es hoy un prototipo funcional del lado del cliente: ~30 módulos HTML autocontenidos que persisten en localStorage del navegador, con control de acceso por perfil en la capa de interfaz. Esto valida procesos, flujos, indicadores y reglas de negocio, pero no constituye un sistema de producción: los datos viven en cada equipo, no hay autenticación real ni integración con los sistemas institucionales.

Esta especificación define la capa de backend, seguridad e integraciones necesaria para convertir el prototipo en una plataforma institucional, conservando la lógica y la experiencia ya construidas.

Principio rector: no reescribir lo validado. El frontend actual (HTML/JS) puede conservarse conectándolo a una API; la lógica de negocio ya probada se traslada al servidor con el mismo modelo de datos.

2. Arquitectura objetivo (capas)

Presentación — Frontend actual (HTML/JS) servido por el backend o migrado a SPA (React); mismos módulos y flujos. Consume API por HTTPS.
API — REST/GraphQL (Node.js/.NET/Python) con API Gateway; una API por dominio (contencioso, instrumentos, patrimonio, IAM, transparencia, etc.).
Servicios de dominio — Reglas de negocio (turnado, trazabilidad, alertas, cálculo de indicadores) migradas del cliente al servidor.
Datos — Base relacional (PostgreSQL/SQL Server); almacén de objetos (S3/Azure Blob) para documentos (hoy en base64); motor de búsqueda (OpenSearch/Elastic) + base vectorial para IA.
Identidad — OAuth2/OIDC con SSO institucional (Microsoft Entra ID / Google Workspace) + el módulo IAM como capa de RBAC/ABAC.
Integración — Conectores a sistemas UdeG y externos (ver §5) vía API Gateway / bus de eventos.
Analítica — Power BI / Microsoft Fabric embebido para tableros ejecutivos.
Observabilidad y seguridad — Bitácora inalterable, monitoreo, respaldos, cifrado, WAF.

4. Seguridad e identidad (backend del módulo IAM)

El módulo Administración Central de Usuarios y Seguridad ya define la política (usuarios, roles, matriz de 17 privilegios, cupos, licencias, auditoría). Falta su enforcement real en el servidor:

  • Contraseñas: hash con Argon2/bcrypt + salt; nunca en claro (hoy solo se marca passSet).
  • SSO + 2FA: OIDC contra Microsoft Entra ID; segundo factor TOTP/push obligatorio para administradores.
  • Sesiones: JWT de corta vida + refresh; cierre remoto real; expiración por inactividad; registro de dispositivos.
  • RBAC/ABAC: la matriz de privilegios y la segregación por adscripción (coordinación/unidad/CU) se validan en cada endpoint, no solo se ocultan en el menú.
  • Bitácora inalterable: append-only con encadenamiento por hash (o WORM); IP, equipo, navegador reales.
  • Restricciones: por IP/rango, horario y ubicación (hoy parámetros; aplicarlas en el gateway).
  • Cupos y licencias: validación de límites por módulo/sistema del lado servidor al crear usuarios.

Normas de referencia: ISO/IEC 27001 e ISO 27002, NIST Cybersecurity Framework, OWASP ASVS. Datos personales: LGPDPPSO / Ley de Protección de Datos de Jalisco — atención especial a datos sensibles (salud, víctimas/DH, biométricos): cifrado en reposo y en tránsito, minimización, anonimización (ya aplicada en DH y Hospitales) y control de acceso estricto.

6. Inteligencia artificial y OCR

Hoy el sistema aplica heurísticas por reglas (extracción por patrones, recomendaciones simples, predicción de vencimientos). En backend se sustituyen por servicios reales:

CapacidadEstado actualServicio backend
OCR de imágenes/PDFPor reglas sobre texto pegadoAzure Document Intelligence / AWS Textract / Google Document AI
Búsqueda semánticaPalabras clave + filtrosEmbeddings + base vectorial (pgvector / OpenSearch KNN)
Clasificación documental / extracciónReglasLLM + modelos entrenados
Generación/revisión de contratosCláusuloteca manualLLM + cláusuloteca (RAG) con revisión humana
Predicción (vencimientos, riesgo, consumo)HeurísticaModelos predictivos / Power BI + ML
Asistente jurídicoChat sobre datosRAG sobre el acervo con control de acceso
Toda IA sobre datos sensibles (salud, DH, personales) debe respetar el control de acceso y la protección de datos; no exponer datos personales a modelos externos sin base jurídica y anonimización.

8. Requisitos no funcionales y cumplimiento

  • Seguridad: ISO 27001/27002, NIST CSF, OWASP ASVS; cifrado en reposo y tránsito; WAF; gestión de vulnerabilidades.
  • Protección de datos: LGPDPPSO y Ley estatal; avisos de privacidad; datos sensibles cifrados y con acceso restringido; anonimización.
  • Gestión documental: ISO 15489; catálogo de disposición y archivo (Art. 8 fr. XIII); versionamiento y trazabilidad.
  • Gobierno de TI: COBIT; servicio ITIL v4 (ya modelado en Help Desk); BPMN 2.0 para los flujos.
  • Disponibilidad: respaldos, recuperación ante desastres, alta disponibilidad; monitoreo y alertas.
  • Accesibilidad y calidad: ISO 9001; accesibilidad web; auditoría de accesos y cambios.
